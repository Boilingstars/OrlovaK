# K⁺(H₂O)ₙ | полный воспроизводимый расчётный пакет (n = 4–14)

**Состояние на 04.11.2026: только готовые входы, код и пустые шаблоны.** В ZIP **НЕТ** реально вычисленных энергий/минимумов калия. Расчёты выполняются на компьютере/сервере с xTB 6.7.1. Не путать с завершёнными расчётами Cs⁺ из другого проекта.

## Цель

Повторить исследовательский конвейер для катиона K⁺ на 11 стехиометриях — 100 независимых GWH-стартов на каждую, итого 1100 входов, — и отобрать для Дениса **минимальную энергию при геометрически подтверждённой нужной координации**. Координационное число MDAtom, `radius[A]`, CoCoS — диагностические характеристики, а не обязательные фильтры окончательного отбора.

## Параметры, согласованность которых проверена

| Настройка | Значение | Статус |
|---|---:|---|
| Катион | K⁺ | +1; 18 электронов у свободного иона K⁺, замкнутая оболочка |
| Комплекс | K₁OₙH₂ₙ, n=4–14 | 3n+1 атомов, чётное число электронов |
| Заряд / мультиплетность | +1 / 1 | xTB `--chrg +1 --uhf 0`; GWH `--Charge +1 --Mult 1` |
| Кристаллический радиус Шеннона K⁺, КЧ=6 | **1,52 Å** | Шкала *crystal radii*, отличается от эффективного радиуса 1,38 Å |
| Эффективный радиус K⁺, КЧ=6 | **1,38 Å** | Не складывать молча с кристаллической шкалой |
| Условный вклад нейтральной водной молекулы к радиальной эвристике | **1,52 Å** | Перенят из *Cs*-методики как модельный вклад, **не** радиус Шеннона для O в воде |
| **Начальный параметр GWH** | **3,04 Å = 1,52 + 1,52** | Расстояние до **центра зарядов SPC/E H₂O**, не до кислорода; не равновесный K–O |
| Начальная геометрия | 11 нормированных сферических упаковок Sloane, n=4–14 | SHA256, единичная длина, углы проверены |
| Глобальный базовый seed | 20261104 + n×1000 + i | reproducible для i=0…99 |
| GWH ориентации | SciPy `Rotation.from_euler('zyz')`, extrinsic | Идентично исходному коду GWH, не менять на uppercase `ZYZ` |
| GWH оптимизация | Ограничены опорные точки, оптимизируются ориентации (Powell) | ТОЛЬКО предоптимизация |
| xTB | **GFN2-xTB/ALPB(water)** | xTB **6.7.1**, фиксировать фактический build/hash |
| Свободный минимум | `normal` → `tight` → Hessian; внутренние частоты > 0 см⁻¹ | 3N−6; седла отдельно; не включать в минимумы |
| CoCoS | CritFreq 125 см⁻¹, также 83.4/166.8 | Только для диагностической уникальности, **не** для первичного выбора минимума |
| MDAtom | `-e K --RunWaterAnalysis --DoNotUseRounding --scale 1.0` | Радиус VdW K в копии MDAtom = 2,75 Å; альтернативный `--UseCovRad` — только независимый тест |
| Формальный MDAtom фильтр | 0 ≤ n − #water ≤ 0.15 | Только сравнимая с Cs диагностика; **не финальное правило** |

**Почему не взяты 2,90 Å?** Это сумма 1,38 Å (эффективный K⁺) и условных 1,52 Å для воды: разные соглашения радиусов. При прямом переносе Cs-методики (кристаллический радиус центрального иона + тот же водный вклад) получается 3,04 Å. Литература описывает ожидаемые K–O ≈2,72 Å для шестикоординированного гидрата — это проверочный ориентир для **оптимизированных** K–O, не точная координата фиксации GWH. Если результаты пилота указывают на патологию стартовой геометрии, провести **отдельный помеченный** тест 2,90 Å в новом `--tag` (не смешивать с `full_100`); сначала согласовать с исследовательской группой.

Ссылки и детали: [`docs/PARAMETER_VERIFICATION.md`](docs/PARAMETER_VERIFICATION.md).

## Быстрый запуск Linux / WSL Ubuntu (предпочтительно)

```bash
cd K_hydration_full_workflow_2026-11-04
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
xtb --version                         # обязан показывать 6.7.1
python tests/selftest.py              # проверка математики, НЕ xTB
python tests/test_k_review.py         # синтетический unit test; НЕ химические результаты
python scripts/k_pipeline.py check   # полная проверка 11 vecfle, SHA и xTB
python scripts/k_driver.py --dry-run  # просмотр команд без вычислений
python scripts/k_driver.py --workers 2 --relax-workers 1 --threads 1
```

Сам xTB **в комплект не включён**; скачивать исполняемую сборку 6.7.1 нужно из официального репозитория и поместить в `$PATH`. При нехватке памяти понизить `--workers` и `--relax-workers` до 1. На многопроцессорном сервере повышать только после мониторинга ОЗУ/нагрузки. Один запущенный драйвер: lock не допускает второй одновременный запуск.

## Этапы и каталоги

`inputs/K_04`…`K_14` (из источника Sloane) → `runs/K_XX/full_100/gwh` → `constrained_100_multiframe.xyz`, `energies.csv` → `free` (normal/tight/Hessian) → `verified` (только минимумы) → `cocos`, `mdatom`, `shell` (диагностические результаты) → `final` (старый КЧ-фильтр, только сравнение) → `analysis/` + `review/output/` (основные кандидаты для ручной проверки). Дополнительно итоговый архив результатов после полного исполнения сборки.

**Важный смысл нулей:** отсутствие прошедших формальный КЧ-фильтр *не значит* отсутствие частотно подтверждённых минимумов. `radius[A]` — **взвешенное среднее расстояние** до условных центров H₂O, а не граница оболочки. `--UseCovRad` меняет веса и не превращает его в порог. Соответствующие правила написаны в [`CURSOR_AGENT_PROMPT.md`](CURSOR_AGENT_PROMPT.md).

### Контроль состояния и возобновление

```bash
python scripts/k_driver.py --status
python scripts/k_driver.py                # продолжает готовые шаги, НЕ дублирует процессы
python scripts/k_driver.py --analysis-only # переанализировать результаты CoCoS/MDAtom; без GWH/xTB
python scripts/k_coordination_review.py  # только K–O и ранжирование кандидатов, без xTB
```

Результаты **не нужно** принимать по самотесту или сухому прогону. Если Hessian дал мнимую внутреннюю моду, структура не является подтверждённым минимумом. Подбор координат/метода мод может осуществляться только по согласованию, в отдельной серии, с журналированием происхождения.

## Для сдачи Денису

1. Использовать **все** частотно подтверждённые геометрии; CoCoS нужен для дополнительной уникальности, не ограничивает список кандидатов.
2. Для каждого n найти самый низкоэнергетический минимум *с геометрически подтверждённым нужным КЧ*. Вытянутый октаэдр и тригональную бипирамиду различать по XYZ, углам, H-связям, расстояниям K–O, а не по `#water`.
3. Отчёт `review/output/K_coordination_minima_review.md` даёт кандидатов и ссылки на XYZ; финальное `ACCEPT` должен установить человек.
4. Если полной оболочки для данного n не найдено, указать `NOT_FOUND_IN_SEARCH` и отдельно привести глобальный минимум с его фактической координацией.
5. Перед передачей проверить GWH/Hessian/энергии из сырьевых логов, не полагаться только на цифры из Excel.
