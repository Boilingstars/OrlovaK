# Контроль исходных физических и вычислительных параметров K⁺

Здесь отдельно приведены **справочные данные**, **эвристика начальной геометрии**, **настройки программ** и **невычисленные результаты**. Не подменять одно другим.

## Проверка 1 — атом и электронная конфигурация

- K (Z=19), заряд +1 → электронов у иона K⁺ = 18 (`[Ar]`). Каждая нейтральная H₂O добавляет 10 электронов → `18+10n` всегда чётно. Исходная модель — замкнутый синглет, мультиплетность 1, xTB `--uhf 0`, общее `--chrg +1`.
- На каждый n — ровно 1 K, n O и 2n H; `3n+1` атомов в XYZ. Протокол не использует нейтральный K, K⁻ или ионы Na/Cs.

## Проверка 2 — размеры и выбор шкалы

Shannon 1976 сообщает *effective ionic radius* K⁺(VI) **1,38 Å** и соответствующий *crystal radius* **1,52 Å** (из работы и последующих таблиц; таблица сравнения см. источник).

В старом пакете цезия стартовая эвристика была рассчитана по **crystal radius** Cs⁺(VI) **1,81 Å** и модельному вкладу для O воды **1,52 Å**: 1,81+1,52=3,33 Å. **Мы не смешиваем** шкалы: в новом пакете используем K⁺(VI) crystal **1,52 Å** + тот же модельный вклад H₂O **1,52 Å** → **3,04 Å**.

Сумма задаёт положение *центра зарядов SPC/E воды* в Glorious Water Hole, а не «расстояние K–O 3,04 Å» и не доказательство любого КЧ. Само значение 1,52 Å для H₂O — **сохранённое из прежнего протокола соглашение**, его нельзя выдавать за экспериментальное свойство гидрата калия.

Для проверки физического масштаба: исследование гидратации щелочных катионов (Mähler & Persson, Inorg. Chem. 2012, DOI ниже) приводит ожидаемые K–O около **2,72 Å для КЧ=6** и **2,80 Å для КЧ=7**. Эти числа получены из анализа растворов и структурных данных — не универсальны для каждого конечного кластера с ALPB, и **не фиксируются** при свободной оптимизации.

## Проверка 3 — радиусы, использованные MDAtom (отличаются от Shannon)

В исходной **неизменённой** копии `vendors/MDAtom/atom_local_environment_computer.py`:

- K `vdwRad = 2.750 Å`, `covRad = 1.960 Å`;
- по умолчанию `--scale 1.0` и **без** `--UseCovRad` для водного окружения → `sigma=2.75 Å` (весовая функция);
- `--UseCovRad` изменяет выбор `sigma`, а не физическую границу первой оболочки;
- вычисляемый `radius[A] = Σ_i r_iP_i / Σ_iP_i`, где `r_i` — расстояние до условного центра молекулы воды (см. код `CalcWaterPosAndDipole`, `ComputeWaterEnvironment`). **Ни в каком случае не отсекайте воду по `radius[A]`.**
- Сообщаемое `#water` есть либо сумма непрерывных нормированных весов при `--DoNotUseRounding`, либо сумма округлений **отдельных вкладов**, а не `round(Σweights)`. Оба значения — дескрипторы, нужный КЧ необходимо проверить по геометрии.

## Проверка 4 — исходные упаковки и ориентации

Источник: N. J. A. Sloane, R. H. Hardin, W. D. Smith и др., таблицы сферических упаковок (ссылки ниже). В комплекте есть оригинальные `pack.3.n.txt` (как в пакете Cs), единичные направления и нормированные `K_nn/packing.vecfle`. Для n=4 углы между любыми вершинами 109,471°, для n=6 октаэдр 90°/180°. Все 11 наборов сравниваются с исходными raw packings на строгой точности по координатам и SHA256. Минимальные углы остальных n совпадают с опубликованными списками 3D spherical packings.

GWH: неизменённый `Rotation.from_euler('zyz', ...)` (строчные `zyz` = extrinsic SciPy); не заменять uppercase. При генерации каждая стартовая структура получает воспроизводимый случайный seed.

## Проверка 5 — метод и процесс

GFN2-xTB, `--alpb water`, +1, синглет. Сначала оптимизация **только ориентаций** в GWH с фиксированными опорными точками; затем **свободная** геометрическая оптимизация `--opt normal`, затем `--opt tight`; Hessian должен иметь 3N−6 *внутренних* положительных мод. Не считать ограниченные структуры окончательными минимумами. Не признавать оптимизацию успешной по наличию `xtbopt.xyz` без подтверждённого `GEOMETRY OPTIMIZATION CONVERGED`.

Входы разработаны из Cs-репозитория, **реальные расчёты K здесь не выполнялись**. Нулевые/пустые таблицы до запуска не являются физическим результатом.
